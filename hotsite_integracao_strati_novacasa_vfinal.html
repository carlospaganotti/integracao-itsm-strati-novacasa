Exemplo de chamada autenticada — SoftExpert 3.0.0
curl -X POST 'https://novacasa.softexpert.com/apigateway/v1/workflow'
  -H 'Authorization: <api_key_usuario_integracao>'
  -H 'Content-Type: application/json'
  -d '{ "processId": "CHAMADO-N1", "workflowTitle": "Chamado HaloPSA #TKT-001", "userId": "strati.integracao", "tables": [...] }'
⚠ Requisito técnico: Usuário de Integração Dedicado
A SoftExpert recomenda a criação de um usuário exclusivo para integrações com: licença MANAGER obrigatória · apenas 1 grupo de acesso vinculado · sem sincronização com Active Directory · não utilizado para acesso cotidiano ao sistema. As credenciais devem ser centralizadas na tela DI004 para injeção automática nas fontes de dados.
Endpoints Confirmados v3.0.0

APIs documentadas para
o projeto de integração

Endpoints extraídos diretamente da documentação oficial SoftExpert Suite 3.0.0, relevantes para o fluxo de chamados com o HaloPSA.

Criar Workflow (Nova API v3.0) ★ Principal
POST /apigateway/v1/workflow
Cria uma instância de workflow com campos de formulário, tabelas e anexos em uma única requisição JSON estruturada.
processIdREQIdentificador do processo de chamado N1
workflowTitleREQTítulo da instância / chamado
userIdMatrícula do usuário iniciador
tables[ ]Campos do formulário: id + value por tipo
attachments[ ]Anexos via filereference (hash)
✓ Documentado v3.0.0
Upload de Arquivos
POST /apigateway/v1/file/upload
Importa arquivos eletrônicos (PDF, imagens, planilhas) e retorna hash único para referenciar em outras requisições.
fileREQmultipart/form-data — arquivo a ser enviado
✓ Documentado v3.0.0
Consultar Workflow (Instância)
GET /apigateway/se/exp/chatbot/api/instance.php
Consulta instâncias de workflow existentes por usuário, produto e status. Retorna OID, identifier, título e status do SLA.
cdProductREQ39 = Workflow
cdUserREQCódigo do usuário
fgStatusFiltro por situação
✓ Documentado v3.0.0
Adicionar Comentário
POST /apigateway/se/exp/chatbot/api/task/comment.php
Inclui histórico de comentário em uma instância de workflow. Usado para registrar atualizações do HaloPSA no chamado SoftExpert.
idInstanceREQIdentificador da instância
cdProductREQ39 = Workflow
textREQTexto do comentário / atualização
✓ Documentado v3.0.0
Registros em Tabela Relacionada
POST /apigateway/se/workflowengine/v1/workflow/table-related-records
Inclui registros em tabelas de formulário descendente. Suporta até 100 registros por requisição. Inclui fields, relationships e files.
workflowIdREQIdentificador do workflow
records[ ]REQArray de registros com fields, relationships, files
✓ Documentado v3.0.0
link-api / instance-data ⚠ PENDENTE
Workflow — métodos link-api e instance-data
Dois dos 6 métodos do componente Workflow ainda não foram extraídos. O link-api pode ser o mecanismo de callback externo (fluxo de retorno HaloPSA → SE). O instance-data retorna campos completos de uma instância.
Responsável: Nova Casa — extrair doc. 3.0.0
Fluxo Técnico

Como o chamado percorre
os dois sistemas

Fluxo de 4 etapas com endpoints confirmados, exceto a Etapa 4 que depende da confirmação do mecanismo de retorno do SoftExpert.

01
Abertura
Chamado N1 criado no SoftExpert

Colaborador Nova Casa preenche formulário de atendimento no SoftExpert 3.0.0 e submete o chamado.

Origem: SoftExpert
Ator: Usuário final
Formulário: form-api
02
Roteamento
SE envia via API para o HaloPSA

Automação do SoftExpert aciona Fonte de Dados REST, enviando payload JSON completo para o HaloPSA.

POST /apigateway/v1/workflow
Auth: JWT Bearer Token
Payload: JSON estruturado
03
Atendimento
Analista Strati trata no HaloPSA

Ticket criado no HaloPSA via API REST OAuth2. Analista Strati trata conforme SLA contratado.

POST /api/Tickets (Halo)
Auth: OAuth2 Client Creds
Evento: Ticket Updated
04
Retorno ⚠
Status atualizado no SoftExpert

HaloPSA notifica o SoftExpert via webhook. Mecanismo receptor do SE pendente de confirmação.

⚠ Pendente confirmação:
link-api ou Aplicações Ext.
Responsável: Nova Casa
Veredicto Técnico

Viabilidade por componente
baseada na doc. v3.0.0

Avaliação atualizada com base nos endpoints e mecanismos extraídos diretamente da documentação oficial SoftExpert 3.0.0.

📤100% Viável
SoftExpert → HaloPSA

POST /apigateway/v1/workflow com payload JSON completo. Fonte de Dados REST com Bearer Token no header. Totalmente documentado na v3.0.0.

🔐100% Viável
Autenticação JWT

API Key JWT no header Authorization. Usuário dedicado com licença MANAGER. Credenciais centralizadas no DI004. HTTPS obrigatório em produção.

📎100% Viável
Upload de Anexos

POST /apigateway/v1/file/upload retorna hash único. Referenciado no payload do workflow via attachments[ ]. Fluxo completo documentado.

💬100% Viável
Comentários / Tratativas

POST /task/comment.php permite ao HaloPSA registrar atualizações de tratativa diretamente no histórico do chamado no SoftExpert.

📥Condicional
HaloPSA → SoftExpert (Retorno)

Webhook do HaloPSA (Ticket Updated) precisa de endpoint receptor no SE. Depende de confirmar link-api ou Aplicações Externas na doc. 3.0.0.

🤖A Explorar
Servidor MCP (IA)

Novidade exclusiva v3.0.0. Integração com agentes de IA via Model Context Protocol. Pode automatizar roteamento inteligente de chamados entre os sistemas.

Pendências Críticas

O que ainda precisa
ser resolvido

Itens pendentes com responsáveis definidos, impacto no projeto e ação requerida. Sem estes itens, o fluxo de retorno não pode ser implementado.

🚨 Atenção: 3 pendências bloqueiam o fluxo de retorno (HaloPSA → SoftExpert)
O fluxo de saída (SoftExpert → HaloPSA) está 100% documentado e pode iniciar implementação. O fluxo de retorno depende da resolução das pendências P1, P2 e P3 abaixo, todas de responsabilidade da equipe Nova Casa / SoftExpert.
Workflow > método link-api — detalhamento completo
P1 · Crítico
Um dos 6 métodos do componente Workflow (listado na tabela como "API link") ainda não foi extraído. O nome sugere fortemente que é o mecanismo de conexão/callback com sistemas externos — pode ser exatamente o endpoint receptor para o webhook do HaloPSA.
ResponsávelNova Casa — Admin SoftExpert
AçãoExtrair seção link-api do portal 3.0.0
StratiAguarda para mapear endpoint
📍 Onde buscar: portal developer.softexpert.com > Componente Workflow > método link-api
Workflow > método instance-data — dados do workflow
P2 · Crítico
O método "Dados do workflow" permite leitura completa dos campos de uma instância específica. Essencial para que o HaloPSA consulte o status e os dados de um chamado aberto no SoftExpert, fechando o ciclo de rastreabilidade bidirecional.
ResponsávelNova Casa — Admin SoftExpert
AçãoExtrair seção instance-data do portal 3.0.0
StratiAguarda para mapear payload de retorno
📍 Onde buscar: portal developer.softexpert.com > Componente Workflow > método instance-data
Aplicações Externas — detalhamento técnico completo
P3 · Crítico
A documentação menciona "Aplicações externas permitem integração de sistemas e serviços de terceiros" mas não detalha os mecanismos. Pode conter webhook outbound nativo, endpoint receptor de dados externos ou callback configurável — todos críticos para o fluxo de retorno.
ResponsávelNova Casa + Suporte SoftExpert
AçãoExtrair ou solicitar ao suporte SE
StratiAguarda confirmação da existência de webhook
📍 Alternativa: acionar suporte SoftExpert questionando diretamente: "O SE 3.0.0 suporta webhook outbound/inbound para sistemas parceiros?"
Mapeamento de campos — payload de-para HaloPSA ↔ SoftExpert
P4 · Importante
O payload da nova API POST /apigateway/v1/workflow recebe campos via tables[ ].fields[ ]. É necessário mapear exatamente quais campos do formulário N1 do SoftExpert correspondem a quais campos do ticket HaloPSA (categoria, impacto, urgência, descrição, etc.).
ResponsávelNova Casa — formulário N1
Co-resp.Strati — campos HaloPSA
QuandoReunião técnica conjunta
📍 Ação: Nova Casa documenta campos do formulário SE; Strati documenta campos obrigatórios do HaloPSA; reunião para alinhar o de-para.
Usuário de integração e credenciais DI004 — criação no ambiente
P5 · Importante
A documentação v3.0.0 exige criação de usuário dedicado (licença MANAGER, sem AD, 1 grupo de acesso) e registro das credenciais do HaloPSA no DI004. Estes são pré-requisitos para qualquer teste de integração no ambiente de homologação.
ResponsávelNova Casa — Admin SoftExpert
AçãoCriar usuário + cadastrar DI004
StratiFornece Client ID + Secret HaloPSA
📍 Pré-requisito para homologação. Deve ser criado antes dos primeiros testes de chamada API.
Ambiente de homologação SoftExpert 3.0.0
P6 · Importante
Para executar o ciclo completo de testes (abertura → roteamento → tratativa → retorno) é necessário acesso a um ambiente sandbox/homologação do SoftExpert 3.0.0 com o processo de chamado N1 configurado e o usuário de integração ativo.
ResponsávelNova Casa — TI / Infra
AçãoProvisionar acesso sandbox
StratiExecuta testes de integração
📍 Sem este ambiente, os testes de integração não podem ser iniciados.
